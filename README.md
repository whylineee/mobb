# AgentWatch

Локальний read-only монітор Claude Code та Codex для macOS: термінальний дашборд із токенами й графіками, живі сесії в ізометричному 3D-офісі, детальна панель, хронологія і резервний 2D-список.

## Запуск

Потрібні **Node.js 24** і **pnpm 11**.

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm agentwatch setup
pnpm agentwatch start
```

Відкрийте посилання, надруковане у терміналі. Ключ у фрагменті `#token=…` залишається локальним і після відкриття прибирається з адресного рядка. Не публікуйте це посилання.

Сервер слухає тільки `127.0.0.1:4317`. Закриття браузера не зупиняє моніторинг; `Ctrl+C` у терміналі зупиняє AgentWatch, залишаючи агентів працювати. Автозапуск не встановлюється.

```sh
pnpm agentwatch doctor
pnpm agentwatch hooks uninstall
```

`setup` зберігає наявні hooks і створює приватні резервні копії налаштувань. Повторний запуск не дублює записи. `uninstall` видаляє тільки власні обробники, зберігаючи подальші зміни користувача. Якщо агент не підхоплює нові hooks автоматично, відновіть або перезапустіть його сесію.

Одночасні `setup`/`uninstall` серіалізуються через маленький coordination-файл `*.agentwatch-lock.sqlite` біля налаштувань агента. Він не містить сесій чи ключів; його залишають після uninstall, щоб паралельні команди користувалися тим самим OS-lock. Після аварійного завершення процесу блокування звільняє SQLite.

## Термінальний дашборд

```sh
pnpm agentwatch tui
pnpm agentwatch tui --ascii --mono
pnpm agentwatch stop
```

`tui` під’єднується до наявного daemon або запускає його у фоні. `q` і `Ctrl+C` закривають лише TUI; `stop` зупиняє моніторинг, залишаючи агентів працювати. Фонові діагностичні повідомлення записуються у приватний `~/.agentwatch/daemon.log`, без ключа UI. Одночасно можна відкрити кілька TUI.

Глобальні лічильники сесій і субагентів не залежать від фільтрів чи ліміту вебогляду у 200 сесій. Пов’язана дочірня сесія рахується один раз. Пошук і фільтр стану змінюють лише таблицю; проєкт та провайдер — також аналітику.

Таблиця і лічильники показують підтверджені відкриті сесії та субагентів; завершені й непідтверджені історичні записи до них не входять. Після завершення відповіді відкрита сесія відображається як «Очікує запиту». Після запуску монітора раніше відкриті сесії можуть не з’явитися до нового живого сигналу: наявність транскрипту чи завантаженого процесу Codex не підтверджує відкриту вкладку.

Періоди: остання година, 24 години або 7 днів. Токени збираються від початку спостереження; старі логи задають baseline, без імпорту минулих витрат. Usage та щохвилинні знімки активності зберігаються окремо протягом 7 днів. Після перезапуску старі сесії потребують нового підтвердження, а прогалини на графіку не заповнюються вигаданими значеннями.

У таблиці показано **власні** токени агента. Cache входить в input, reasoning — в output; їх не додають вдруге. `—` означає недоступне значення, `in:` — відомий input при недоступному total, «частково» — неповне охоплення. Для Claude assistant usage підтверджує input/cache; output із message-start не видається за фінальний. Гроші не обчислюються.

Ліміти Codex у верхній частині TUI показують залишок п’ятигодинного та тижневого вікон і час їх скидання. Демон раз на п’ять хвилин запитує ліміти через локальний Codex app-server; це ліміти облікового запису, а не окремих сесій. Якщо Codex недоступний, авторизація не підтримує цей запит або дані відсутні, показується «недоступні» чи `—`.

Мінімальний розмір — 80×24. Від 140×30 дашборд показує список агентів, деталі вибраного агента й графіки поруч; у меншому вікні `Enter` відкриває деталі, а `g` — графіки. Після зміни розміру компонування оновлюється автоматично. `?` відкриває довідку; `t/p/j/s` змінюють період/провайдера/проєкт/стан, `1/2/3` — графік, `b` — розбивку, `r` скидає фільтри. `--ascii` замінює графічні рамки й діаграми, `--mono` або `NO_COLOR` вимикає колір.

## Як читати офіс

- Один робот — одна сесія `provider:sessionId`. Однаковий проєкт не об’єднує сесії.
- Робот показує лише підтверджену поточну роботу або очікування дії користувача. Після завершення відповіді він зникає одразу; відкрита сесія переходить у «Очікує запиту» й залишається у списку та таскборді.
- Після підтвердженого завершення сесії робот також зникає одразу. Уже відкрита панель лишається доступною.
- Історичний транскрипт сам по собі не підтверджує відкритість: такі сесії мають стан «Невідомо», доки не з’явиться живий сигнал.
- `PermissionRequest` означає перевірку політики дозволів. Позначка «Потрібна увага» вимагає окремого підтвердження очікування користувача.
- PID, CPU, RAM і субагенти показуються лише за наявності доказового зіставлення. Метрики спільного Codex desktop/app-server не приписуються окремій сесії.
- Повні запити та команди розгортаються за кліком. Текст обмежується 65 536 одиницями UTF-16 на поле з позначкою скорочення; обсяг у UTF-8 байтах залежить від символів.
- Таймлайн підтримує підвантаження попередніх подій до 200 записів у пам’яті. Прокрутка до нових подій призупиняється під час ручного перегляду.
- SSE передає компактні огляди; повні тексти панель запитує окремо. Початковий огляд обмежений 200 сесіями з пріоритетом відкритих; якщо записи не ввійшли в огляд, інтерфейс явно показує їхню кількість. Це не видаляє дані з SQLite.
- Список сесій доступний завжди; за відсутності WebGL відкривається автоматично. Є знижена анімація та клавіатурна навігація.

Особливість Codex: закриття або перемикання вкладки не обов’язково завершує runtime-сесію. За документацією поточної версії вона може лишатися завантаженою протягом 30 хвилин після від’єднання останнього клієнта. AgentWatch не підміняє цей життєвий цикл таймером неактивності.

## Приватність і зберігання

Дані — у `~/.agentwatch` (каталог `0700`, БД і ключі `0600`). Окремі ключі обмежують доступ до UI та приймання hooks. Перевіряються Host і Origin; відкритого CORS немає. Немає зовнішніх шрифтів, моделей, CDN чи аналітичних SDK.

SQLite зберігає історію подій до **7 днів**, зокрема для відкритих сесій. Додаткові межі — **10 000 подій на сесію** та **100 000 загалом**: при їх досягненні найстаріші події видаляються, тому доступна історія може бути коротшою за 7 днів. Вікове очищення виконується при старті й щогодини, кількісні межі підтримуються під час приймання подій. Поточний стан підтверджено відкритої сесії зберігається незалежно від обрізання її історії та перезапусків демона. Після перезапуску її відкритість потребує нового підтвердження, але знімок захищений до підтвердженого завершення. Завершені сесії та сесії, відкритість яких не була підтверджена, очищаються після 7 днів без активності.

Демон кешує до **256 повних сесій**; решту читає зі SQLite за потреби. Витіснення з кешу не видаляє сесію. Це межі кількості записів, а не точна квота RAM чи розміру БД: обсяг поточних станів залежить від кількості сесій і тексту. Оновлення CPU/RAM передаються без повторного завантаження повного тексту у відкриту панель.

Оригінальні файли Claude/Codex не змінюються. Окремий екран архіву та повні raw-логи відкладені.

Внутрішні інструкції й reasoning не імпортуються. Відомі ключі, паролі, bearer-токени та credentials в URL маскуються до запису. Це не гарантія виявлення довільного секрету в природній мові; локальна історія може містити приватні промпти, команди й шляхи.

`AGENTWATCH_HOME` змінює каталог AgentWatch. Під час першого налаштування враховуються `CODEX_HOME` і `CLAUDE_CONFIG_DIR`; шляхи також можна змінити у приватному `config.json`. Зміна каталогу AgentWatch вимагає повторного `setup`, щоб hooks використовували правильний шлях.

Помилки доставки без приватного payload зберігаються у bounded-файлі `hook-failures.jsonl` і відображаються в «Стан джерел». Недоступний демон не блокує агента. Hooks повертають тільки `{}`, без рішень щодо дозволів чи продовження.

## Розробка й перевірки

```sh
pnpm test
pnpm typecheck
pnpm build
pnpm exec playwright install chromium
pnpm test:e2e
pnpm format:check
```

Тести використовують тимчасові каталоги та окремий сервер `127.0.0.1:4318`; вони не змінюють справжні налаштування агентів. Браузерні fixtures існують лише в тестовому сервері, не в продукті.

Після зміни UI запускайте `pnpm build` перед браузерними тестами. Для автоматичного перезапуску демона можна використовувати `pnpm dev`; вебінтерфейс у звичайному запуску віддається зі статичної збірки.

Структура: `shared` — контракти; `daemon` — колектори, БД, CLI, HTTP/SSE; `hook-cli` — обмежена доставка hooks; `web` — Next.js, Zustand і React Three Fiber. Геометрія, меблі, кімната й камера розділені у `components/office/`; вкладки панелі — у `components/session/`. Повторювана геометрія інстансується. При навантаженні знижуються деталізація й тіні, зберігаючи Retina DPR. Анімація обмежена 20 FPS; статична сцена та прихована вкладка не потребують постійного рендерингу.

GitHub Actions виконує всі перевірки на macOS для push і pull request. Залежності, які раніше використовували `latest`, зафіксовані поточними версіями; встановлення використовує frozen lockfile. Dependabot щотижня пропонує оновлення пакетів та CI actions без автоматичного злиття.

План і специфікація — у `docs/superpowers/`. Докази доступності джерел та обмеження — у [telemetry-sources.md](docs/telemetry-sources.md).
